# interview-prep

### 1. 서비스 소개와 선택 이유

| 항목 | 내용 |
| --- | --- |
| 사용자와 목적 | 혼자 면접을 준비하는 사람이 질문을 모으고, 무작위로 출제되는 질문에 답변을 녹음하며 연습하는 React 웹 서비스 |
| 개발 배경 | 면접 질문 정리와 답변 연습을 위해 AI로 빠르게 구현 |
| 발견한 문제 | 같은 파일 안의 중복과 편집으로 생기는 중복을 막지 못함. 파일 등록에서 잘못된 입력도 ‘중복 제외’로 안내 |
| 선택 이유 | AI로 빠르게 만든 기능의 실제 동작을 점검하고 개선하기 위해 선택. 기존 질문과 연습 흐름을 유지하면서 등록 결과를 정확히 안내하는 데 집중 |

### 2. 핵심 흐름과 요구사항

**질문·카테고리 입력 → 추가 → 목록에서 확인 → 면접 연습에 사용**

| 사용자 상황 | 기대 결과 |
| --- | --- |
| 정상 등록 | 목록에 나타나고, 새로고침 후에도 유지 |
| 빈 값·공백만 입력 | 저장하지 않고 입력 안내 |
| 다른 질문과 중복되는 내용 입력 | 직접 입력·파일·편집 모두 같은 기준으로 중복을 판단하고 저장하지 않음 |
| 같은 파일 안에 같은 질문이 여러 번 | 1개만 저장하고, 제외한 개수와 이유 안내 |
| 등록 요청 실패 | 입력을 유지하고 오류에 따라 수정 또는 재시도 안내 |
| 요청 중 버튼·Enter 반복 | 같은 제출로 여러 건이 저장되지 않음 |
| 기존 브라우저에 저장된 질문 | 저장 방식을 전환한 뒤에도 사용 가능 |

### 3. 작업 범위

기존 코드 기준 커밋: `616e72f`.

| 구분 | 내용 |
| --- | --- |
| 기존 기능 | 질문 등록·조회·편집·개별/전체 삭제·파일 업로드, 카테고리 관리, 면접 진행·녹음 |
| 범위를 정한 이유 | 질문 등록의 정확한 결과 안내와 실패 후 재시도에 집중. 편집·삭제 등은 저장 방식 전환 후에도 기존 기능을 유지하기 위해 포함 |

**완료한 개발 환경 정비:** 타입 오류 2건 수정, TS/TSX 린트 적용, 통합 검사 명령 추가. 린트 적용으로 드러난 중복 초기화 Effect와 타이머 함수 참조·의존성도 정리했습니다.

**구현 예정 범위**

| 구분 | 작업 |
| --- | --- |
| 기존 오류 개선 | 직접 입력·파일 등록·편집의 검증 기준 통일, 파일 등록의 제외 사유 안내 수정 |
| 등록 흐름 확장 | API 요청의 처리 중·성공·실패를 화면에 표시. 실패 시 입력 보존·재시도, 반복 제출 처리 |
| 전환에 필요한 연결 | 조회·편집·개별/전체 삭제도 같은 API 저장 경로로 변경. 카테고리별 개수와 면접 시작 연결 유지 |
| 기존 데이터 유지 | 브라우저에 저장된 질문을 Mock 저장소로 이전하고 새로고침 후에도 유지 |
| 검증 | 기존 버그의 재현·수정 확인, 실패·반복 제출·새로고침·데이터 이전 검증 |

| 제외 범위 | 이유 |
| --- | --- |
| 실제 백엔드·로그인 | 프론트엔드의 데이터 접근과 요청 처리에 범위를 한정 |
| 파일 파싱 API | 기존 텍스트 형식은 브라우저에서 처리할 수 있으므로 파싱은 유지하고 저장 경로만 변경 |
| 면접 진행·녹음 개선과 새로고침 복원 | 진행 상태·시간·녹음 저장에 별도 설계가 필요. 세션 시작에 질문 목록을 전달하는 연결만 변경 |
| 카테고리 필터 URL 유지 | 목록 흐름의 개선이지만 저장 방식 전환에 집중하기 위해 제외 |

검토할 코드는 [질문 기능](src/features/questions/), [질문 저장 로직](src/store/questionSlice.ts), [목록과 면접 시작 연결](src/pages/SetupPage.tsx), [세션](src/store/sessionSlice.ts), [카테고리별 개수](src/features/categories/components/CategoryFilter.tsx)입니다.

### 4. 실행 및 확인 방법

| 항목 | 내용 |
| --- | --- |
| 개발 환경 | Node.js `24.15.0`, npm `11.12.1` |
| 의존성 | [package.json](package.json), [package-lock.json](package-lock.json) |
| 추가 설정 | 별도 서버·API 키 불필요. 녹음 시 브라우저 마이크 권한 필요 |
| 파일 입력 예시 | `.txt`의 한 줄이 질문 하나. `일반::자기소개를 해주세요.`로 카테고리 지정 가능 |

저장소 루트에서 실행합니다.

```bash
npm ci
npm run dev
```

| 검사 명령 | 확인 대상 |
| --- | --- |
| `npm run typecheck` | TypeScript 타입 오류 |
| `npm run lint` | JS/JSX·TS/TSX 코드와 React 훅 규칙 |
| `npm run build` | 프로덕션 번들 생성 |
| `npm run check` | 타입 검사 → 린트 → 빌드. 앞 단계가 실패하면 중단 |

터미널에 표시되는 주소로 접속한 뒤 아래 순서로 확인합니다.

| 순서 | 조작 | 확인할 결과 |
| --- | --- | --- |
| 1 | **질문 추가**에서 카테고리와 질문을 입력하고 **추가** 클릭 | 목록에 입력한 질문 표시 |
| 2 | **카테고리**에서 연습할 카테고리 선택 | 해당 카테고리의 질문 표시 |
| 3 | **면접 시작** 클릭 | 선택한 카테고리의 질문으로 면접 시작 |

### 5. 주요 결정과 이유

| 결정 | 이유 |
| --- | --- |
| 입력 검증을 공통 규칙으로 통일 | 직접 입력·파일 등록·편집에 따라 저장 기준이 달라지는 문제 해결. 중복 오류는 API 도입 여부와 관계없이 이 규칙으로 수정 |
| 저장 직전에 중복 재검사 | 화면의 목록이 오래됐거나 요청이 겹쳐도 실제 저장 데이터를 기준으로 판단 |
| 질문 저장을 API + MSW로 전환 | 화면의 데이터 접근을 API로 분리. 실제 백엔드 없이 지연·실패·중복 응답을 재현해 요청 처리·캐시 갱신·화면 상태가 함께 동작하는지 검증 |
| Query와 Zustand의 역할 분리 | 질문의 요청 상태·캐시·목록 갱신은 Query로 통합. 면접 진행·카테고리는 기존 Zustand 유지 |
| 기존 질문과 관련 기능 유지 | 저장 방식 전환 때문에 질문을 다시 등록하거나 편집·삭제·파일 등록 기능을 잃지 않도록 함 |

Mock 데이터는 localStorage에 저장하며, 기기 간 동기화는 제공하지 않습니다.

### 6. AI 활용과 판단

초기 서비스는 AI로 바이브코딩했습니다. 이번에는 AI와 기존 코드를 검토하며 개선할 문제와 작업 범위를 정리했습니다.

| AI에 전달한 맥락 | AI의 제안·지적 | 확인한 내용 | 판단·수정 |
| --- | --- | --- | --- |
| 질문 입력·파일 등록·편집 코드와 저장 로직 | 일괄 등록·편집의 중복 검사 누락 | 같은 질문의 일괄 등록과 편집에서 중복 저장 재현 | 입력 경로별 검증 차이를 핵심 개선 대상으로 선정 |
| API 전환 방향과 기존 화면·스토어 코드 | 조회·등록부터 바꾸고 나머지는 나중에 전환하는 단계 계획 | 편집·삭제는 기존 저장소를 변경하고, `sessionSlice`·`CategoryFilter`도 기존 질문을 읽음. 부분 전환 시 데이터 불일치 위험 | API·Mock·이전 로직 준비와 화면 연결을 분리. 관련 읽기·쓰기 경로는 함께 전환하도록 계획 수정 |
| 빌드·타입·린트 설정과 검증 결과 | 빌드만으로 타입 검증을 보장하지 못하고 TS/TSX 린트도 누락 | 타입 검사 오류 2건과 ESLint 검사 대상 확인 | 타입 오류 수정·TS/TSX 린트 적용. `npm run check`로 타입·린트·빌드 통과 확인 |

### 7. 확인 결과와 남은 문제

**개발 환경 정비 결과**

| 확인 대상 | 방법 | 결과 |
| --- | --- | --- |
| 타입·린트·빌드 | `npm run check` | 모두 통과. 린트 경고 없음 |
| TS/TSX 린트 적용 | 사용하지 않는 TS 변수·조건부 훅 호출 예제를 ESLint에 전달 | 각각 해당 규칙 위반 검출 |
| 기본 화면 흐름 | 브라우저에서 질문 2개 등록 → 면접 시작 → 다음 질문 | 목록·질문 전환 정상, 타이머 진행 및 다음 질문에서 초기화 확인 |

**기존 질문 기능에서 확인한 문제**

| 확인 대상 | 방법 | 기대 결과 | 실제 결과 |
| --- | --- | --- | --- |
| 한 번의 일괄 등록에 같은 질문 2개 | `addQuestions` 직접 호출 | 1개 저장 | 2개 저장. 같은 질문을 다음 호출에서 넣으면 추가되지 않음 |
| 편집으로 다른 질문과 같은 내용 저장 | `updateQuestion` 직접 호출 | 중복 저장 거절 | 같은 내용의 질문 2개 유지 |
| 파일 등록의 제외 사유 안내 | 코드 확인 | 입력 오류와 중복 구분 | 빈 질문처럼 추가되지 않은 항목도 모두 ‘중복 제외’로 표시 |

중복 처리·파일 결과 안내는 아직 수정하지 않았습니다. 위 문제는 함수 실행·코드 검토로 확인했으며 브라우저 재현은 수행하지 않았습니다.

**범위 밖에서 확인한 문제**

| 항목 | 확인한 문제 |
| --- | --- |
| 세션 단축키 | `→`·`N`·`Space` 안내에 대응하는 구현 없음 |
| 녹음 저장 | 취소·실패가 호출자에게 전달되지 않아 목록 추가와 ‘저장됨’ 표시가 이어짐 |
| 화면 이탈 | 녹음 스트림·타이머 정리와 오디오 URL 해제 코드 없음 |

세션·녹음 항목은 코드 검토 결과이며 브라우저 재현 전입니다.
