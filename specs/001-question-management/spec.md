# 001. 질문 등록·관리 개선

`feat/question-management` · 시작 기준 `6b8e97e` · [plan](plan.md) · [tasks](tasks.md) · [README](../../README.md) · [개발 규칙](../../AGENTS.md)

## 1. 목적과 범위

면접 질문을 모으는 사용자가 중복 없이 등록하고 저장·제외 결과를 이해하며, 실패해도 입력을 잃지 않도록 한다. 파일 등록·편집의 중복 검사 누락과, 파일의 빈 질문까지 ‘중복 제외’로 안내하는 문제를 고친다. 추후 서버 연결을 고려해 API 기반 요청 처리로 전환한다.

### 1.1. 개선할 기능

| 기능 | 개선 내용 |
| --- | --- |
| 직접 등록 | 입력 검증, 요청 상태 표시, 실패 후 재시도, 반복 제출 방지 |
| 파일 등록 | 양식 안내, 저장 전 미리보기, 저장·제외 결과 안내 |

### 1.2. 유지할 기능

| 기능 | 유지할 동작 |
| --- | --- |
| 질문 관리 | 조회, 편집, 개별 삭제, 전체 삭제 |
| 면접 연결 | 카테고리별 질문 개수 표시, 선택한 질문으로 면접 시작 |
| 데이터 보관 | 새로 등록한 질문을 새로고침 후에도 유지 |

### 1.3. 제외 범위

| 영역 | 제외 내용 |
| --- | --- |
| 데이터 이전·복구 | 기존 질문·카테고리 옮기기, 브라우저 데이터 삭제 후 복구 |
| 여러 기기·탭 | 기기 간 동기화, 여러 탭에서 동시에 데이터 변경 |
| 서버 구축 | 실제 백엔드, 로그인, 파일 파싱 API |
| 추가 화면 기능 | 미리보기에서 질문 편집, URL에 필터 저장 |
| 면접 진행·녹음 | 동작 개선, 새로고침 후 진행 상태 복원 |
| 응답 유실 복구 | 일반 변경 요청의 저장 여부 확정, 자동 복구 |

**Mock DB**는 MSW가 질문의 조회·등록·편집·삭제에 사용하는 저장 공간이다. 새 Mock DB는 빈 목록으로 시작한다. 기존 질문과 직접 만든 카테고리는 가져오지 않으며, 새 카테고리 저장 데이터도 없으면 기본 카테고리로 시작한다. 기존 데이터는 변경하지 않는다.

## 2. 사용자 흐름

직접 입력 또는 파일 선택 → 검증·미리보기 → 등록 → 목록·결과 확인 → 카테고리 선택 → 면접 시작.

## 3. 동작 규칙

### 3.1. 입력과 중복

| ID | 규칙 |
| --- | --- |
| `R01` | 신규 등록·편집은 앞뒤 공백만 제거해 저장한다. 질문 길이 제한은 추가하지 않는다. 내부 공백·대소문자·문장부호는 유지한다. 신규 질문은 목록 뒤에 추가하고 편집은 위치를 유지한다. |
| `R02` | 빈 질문은 저장하지 않는다. 직접 등록·편집은 입력 안내 후 요청을 막고, 파일은 해당 줄을 입력 오류로 분류한다. |
| `R03` | 앞뒤 공백 제거 → 영문 소문자 변환 → 연속 공백 통일 → 끝 물음표(`?`) 제거 → 끝 공백 제거 순서로 비교한다. 같은 비교 값은 카테고리와 관계없이 중복이다. 다른 기호·문장의 의미는 정규화하지 않는다. |
| `R04` | 직접·파일 등록·편집에 `R01`~`R03`을 동일하게 적용한다. |
| `R05` | 편집 대상 자신은 중복 비교에서 제외한다. 다른 질문과 중복이면 편집을 거절한다. |
| `R06` | 파일 내부 중복은 먼저 나온 유효한 항목과 그 카테고리만 등록 대상으로 삼는다. |

| 기존 내용 | 새 입력 | 기대 판정 |
| --- | --- | --- |
| `자기소개` | `  자기소개  ` | 카테고리가 달라도 중복 |
| `React란?` | `react란?` | 중복 |
| `자기소개를 해주세요` | `자기소개를  해주세요` (공백 2칸) | 중복 |
| `자기소개` | `자기소개?` | 중복 |
| `C++란?` | `C란?` | 다른 질문 |

### 3.2. 직접 등록과 요청 결과

| ID | 규칙 |
| --- | --- |
| `R07` | 요청 중 질문·카테고리·제출 버튼을 잠그고 Enter 재제출을 막는다. 같은 제출은 1회만 전송한다. |
| `R08` | 중복 거절 시 입력 유지·중복 안내·잠금 해제. 자동 재시도하지 않는다. |
| `R09` | 입력 오류는 수정 안내, 저장 전 실패는 입력·선택 카테고리·파일을 유지하고 잠금 해제 후 사용자 재시도를 제공한다. 응답을 받지 못하면 입력을 유지하고 결과 확인 불가를 안내한다. 자동 재전송하지 않으며 사용자가 목록을 확인한 뒤 다시 시도한다. Mock 요청은 오프라인에서도 실행하며 연결 복구 시점까지 보류하지 않는다. |
| `R10` | 오래된 목록·겹친 요청에도 저장 직전의 실제 데이터로 중복을 최종 판정한다. |
| `R11` | 저장 성공 후 재조회만 실패하면 기존 목록을 유지하고 갱신 실패·재조회를 안내한다. 저장 실패로 표시하거나 변경 요청을 다시 보내지 않는다. |
| `R12` | 등록 성공 시 질문 입력만 초기화하고 선택 카테고리는 유지한다. 입력창에서 제출했다면 처리 후 초점을 복원하되 사용자가 다른 요소로 옮긴 초점은 유지한다. 오류·잠금을 해제하고 목록·개수를 갱신한다. |
| `R13` | 다른 카테고리로 등록해도 현재 필터를 유지하고 “○○ 카테고리에 추가됨”을 안내한다. |

### 3.3. 파일 양식과 등록

파일 선택 옆에 카테고리 드롭다운을 두고 `일반`을 기본 선택한다. 파일 선택은 미리보기만 만들며 등록 버튼을 눌러야 저장한다.

| ID | 규칙 |
| --- | --- |
| `R14` | `.txt` 한 줄에 질문 하나. 질문만 적으면 선택한 카테고리, `카테고리::질문`이면 파일의 카테고리를 사용한다. 첫 `::`로 나누며 카테고리 앞뒤 공백을 제거한다. |
| `R15` | 빈 질문·빈 카테고리·이미 등록됨·파일 내부 중복을 구분해 원본 줄 번호·이유·수정 방법을 안내한다. 빈 줄은 건너뛰되 줄 번호는 유지한다. |
| `R16` | 오류·중복을 제외한 전체 저장 대상을 한 번에 반영한다. 저장 단계 실패 시 일부도 반영하지 않는다. |
| `R17` | 선택 버튼 근처에 양식 안내와 `.txt` 예시 다운로드를 제공한다. 예시는 질문만 적은 줄과 카테고리를 지정한 줄을 모두 포함한다. |
| `R18` | 미리보기에 파일명·질문·적용 카테고리·등록 가능/중복/오류 개수를 표시한다. 사전 중복 안내는 현재 조회 목록 기준이다. |
| `R19` | “등록 가능한 N개 추가” 버튼을 제공한다. 0개면 비활성화하고 이유를 안내하며 빈 파일은 “등록할 질문이 없습니다”로 표시한다. |
| `R20` | 확장자 오류·읽기 실패 시 이유와 재선택 방법을 안내한다. 새 파일 읽기 실패 후 이전 미리보기를 제출하지 못하게 한다. |
| `R21` | 번호·글머리 기호·단일 콜론을 임의로 제거하거나 카테고리 구분자로 해석하지 않는다. |
| `R22` | 저장 전 파일 재선택·취소·카테고리 변경 가능. 카테고리 변경은 질문만 적은 줄에 적용한다. 내용 수정은 원본 수정 후 재선택으로 안내한다. |
| `R23` | 저장 중 등록·파일 선택·취소·카테고리 변경을 잠근다. 성공 시 실제 결과를 표시하고 같은 미리보기 재등록을 막으며 현재 필터를 유지한다. 실패는 `R09`를 따른다. |

> 한 줄에 질문 하나를 적어 주세요. 질문만 적으면 선택한 카테고리로 등록됩니다. 다른 카테고리는 `백엔드::질문`처럼 적어 주세요.

```text
자기소개를 해주세요.
최근 해결한 기술적 문제는 무엇인가요?
프론트엔드::React의 상태와 props 차이는?
백엔드::트랜잭션이란 무엇인가요?
```

| 파일 입력 | 질문 | 카테고리 | 처리 |
| --- | --- | --- | --- |
| `자기소개` | `자기소개` | 선택한 카테고리 | 중복 검사 후 등록 |
| `프론트엔드::React란?` | `React란?` | 프론트엔드 | 중복 검사 후 등록 |
| `프론트엔드::` | 없음 | 프론트엔드 | 질문 입력 필요 |
| `::React란?` | `React란?` | 없음 | 카테고리 입력 또는 `::` 제거 |
| `::` | 없음 | 없음 | 두 입력 오류 안내, 오류 1개로 집계 |
| 빈 줄·공백만 있는 줄 | — | — | 집계 제외 |
| `1. 자기소개` | `1. 자기소개` | 선택한 카테고리 | 번호 포함 |
| `프론트엔드:React란?` | `프론트엔드:React란?` | 선택한 카테고리 | 콜론 포함 |
| `일반::A::B를 설명하세요` | `A::B를 설명하세요` | 일반 | 첫 `::`만 구분 |

집계는 **입력 오류 → 기존 목록 중복 → 파일 내부 중복** 중 처음 해당하는 사유를 사용한다. `등록 가능 + 중복 + 오류 = 빈 줄 제외 항목 수`, 저장 후에는 `실제 등록 + 최종 제외 = 같은 항목 수`다. 저장 시 추가 중복이 발견되면 최종 개수·사유를 안내한다. 파일에만 있는 카테고리는 자동 추가하지 않는다. 질문은 전체 목록에 보이며 사용자가 같은 카테고리를 추가하면 필터로 선택할 수 있다.

### 3.4. 조회·편집·삭제·면접 시작

| ID | 규칙 |
| --- | --- |
| `R24` | 편집 실패 시 폼·입력 유지. 대상이 없으면 삭제됨 안내·목록 재조회 후 해당 대상 저장 재시도를 막는다. |
| `R25` | 개별·전체 삭제 실패 시 목록·개수 유지와 재시도 안내. 개별 삭제 중 필터를 바꿨다가 돌아와도 해당 질문의 실패 안내를 유지한다. 응답 유실은 `R09`를 따른다. |
| `R26` | 최초 조회의 로딩·실패·빈 목록·빈 필터 결과를 구분한다. 실패 시 재조회 제공, 편집·삭제·면접 시작 불가. |
| `R27` | 재조회 실패 시 기존 목록과 작성 중 입력을 유지하고 갱신 실패를 안내한다. |
| `R28` | 선택 카테고리에 질문이 없으면 면접 시작 불가. 조회 완료된 빈 목록에서는 등록 가능. |
| `R29` | 시작 시 선택된 질문으로 세션을 구성하고 이후 Query 갱신을 세션에 반영하지 않는다. |
| `R30` | 편집 저장 중 입력·취소·반복 제출 차단. 성공 시 편집 종료와 기존 위치의 내용·카테고리·개수 갱신. |
| `R31` | 개별 삭제는 별도 확인 없이 요청하고 반복 조작을 막는다. 요청 중 필터를 바꿨다가 돌아와도 삭제 중 상태를 유지한다. 이미 없는 대상도 완료로 처리한다. |
| `R32` | 전체 삭제는 필터와 무관한 전체 개수를 안내하고 확인한다. 취소 시 요청 없음, 처리 중 반복 차단, 성공 시 질문만 비우고 카테고리는 유지한다. 다른 질문 변경 요청 중에는 전체 삭제를 시작하지 않으며, 전체 삭제 중에는 직접·파일 등록·편집·개별 삭제를 막고 작성 중 입력을 보존한다. |
| `R38` | 카테고리는 로컬에 저장·복원한다. 저장된 카테고리가 없거나 복원하지 못하면 기본 카테고리로 시작한다. |

| `A08` | 등록 → 새로고침 → 카테고리 선택 → 면접 시작 | 질문 유지, 선택 질문으로 세션 구성, 빈 카테고리는 시작 불가 |
| `A13` | 기본 선택 `일반` → 예시 파일 → 카테고리 변경/취소 | 질문만 있는 줄의 분류만 변경. 등록 버튼 전 저장 없음 |
| `A14` | 빈 파일·제외 항목만 있는 파일·확장자 오류·읽기 실패 | 조건별 안내, 등록 불가·요청 없음 |
| `A15` | 파일 등록 저장 전 실패 → 재시도 | 첫 저장 0개, 재선택 없이 전체 저장, 성공 후 재등록 불가 |
| `A16` | 미리보기 후 같은 질문 별도 등록 → 파일 등록 | 추가 중복 없음, 최종 개수·제외 사유 안내 |
| `A17` | 변경 요청 응답을 받지 못함 | 입력 유지·결과 확인 불가 안내, 자동 재전송 없음, 목록 확인 후 사용자 재시도 |
| `A18` | 이미 삭제된 질문 편집/삭제 | 편집은 입력 유지·재저장 차단, 삭제는 완료 처리 |
| `A24` | Mock 모드에서 오프라인 조회·등록 실패 → 연결 복구 → 사용자 재시도 | 조회 가능, 실패 시 입력·잠금 해제. 연결 복구만으로 등록 요청 없음. 사용자 재시도 때만 1회 추가 요청 |

## 5. 완료 기준

예시·시나리오를 검증하고 실제 결과를 tasks에 기록한다. 모든 질문 읽기·쓰기는 API로 연결하며 카테고리 개수·세션 시작이 같은 목록을 사용한다. 타입 검사·관련 테스트·빌드 통과, 변경 코드 린트 오류·경고 없음. 기존 녹음·세션 린트 오류 1건·경고 2건은 별도 기록한다.

## 6. 주요 정책의 근거

| 정책 | 선택 이유 |
| --- | --- |
| 중복 비교와 저장 문장 분리 | 표기만 다른 질문의 반복 등록은 막되, 사용자가 작성한 문장은 유지하기 위해서다. `C++`와 `C`처럼 의미가 다른 내용까지 합치지 않도록 비교에서 무시할 문자를 제한한다. |
| 기존 질문·카테고리 이전 제외 | 이전 시 중복 보존·실패 복구를 별도로 설계해야 하므로 등록 흐름 개선에 집중한다. 기존 질문·카테고리는 현재 목록에 반영하지 않지만 원본 데이터는 변경하지 않는다. |
